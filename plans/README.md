# Plans

**This folder is a desk, not a filing cabinet.**

A plan lands here only when a change is big enough to need one &mdash; several files,
real unknowns, more than a handful of steps. Smaller changes get their steps proposed
to you in chat instead, and start when you say yes. Either way you see the steps
before any code is written.

While the work is underway you can read the plan, correct anything wrong, and watch
steps get checked off. When the change is finished and validated, **the plan file is
deleted**.

That is deliberate. A plan describes what someone meant to do on the day it was
written, and nothing updates it when the code moves on. Kept around, it becomes a
confident, out-of-date explanation that the next reader believes &mdash; and Claude
believes it too, which is worse. The code is the only honest account of how the
project behaves, and the commit history still holds every word of every plan if you
ever want to look back.

An empty folder here is the normal state. A file in it means work is in flight.
